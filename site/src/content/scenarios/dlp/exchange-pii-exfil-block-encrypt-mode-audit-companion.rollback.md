## Recommended sequence

This companion adds one non-blocking, audit-only rule, it never restricts mail flow, so rollback
carries none of the mail-flow risk the parent scenario's own rollback procedure warns about. There
is no staged disable/simulation sequence to follow; the rule is either present or removed.

### Remove the rule (only action available)

```powershell
Connect-IPPSSession -AppId $AppId -Certificate $Cert -Organization $TenantDomain
./deploy/Remove-ExchangePiiEncryptModeAuditCompanion.ps1
```

This runs `Remove-DlpComplianceRule -Identity "PII-Exchange-Audit-Encrypt-Exception"`. Unlike a DLP
**policy**, an individual rule has no `Mode`/`Disabled` toggle exposed by this scenario's tooling, 
`Remove-DlpComplianceRule` is the only rollback action. Re-establishing the control means re-running
`deploy/New-ExchangePiiEncryptModeAuditCompanion.ps1` from scratch.

> A rule does support a `-Disabled` property on `Set-DlpComplianceRule`, but this scenario's
> tooling does not script a disable path, for an audit-only rule with no enforcement action to
> stage, removing and re-adding is equally cheap and keeps this fragment's deploy/remove pair
> symmetrical with the rest of this library's convention (create/remove, not create/disable/purge)
> for a single-rule companion.

## What rollback does **not** undo

- **Audit log / alert history.** Alerts and incident reports already generated by this rule are
  retained per their own retention windows regardless of the rule's current state.
- **The parent scenario.** Removing this companion has zero effect on
  `scenarios/dlp/exchange-pii-exfil-block/`'s policy or its three rules, they continue operating
  exactly as before this companion was ever deployed. The documented residual risk
  (`exchange-pii-exfil-block/README.md` §11: exception-group traffic in Encrypt mode is delivered
  in cleartext) simply returns to being **undetected** as well as unblocked, which is the state
  before this companion existed.
- **The business-exception group's membership.** This scenario does not create or manage
  `ExceptionGroupEmail`, removing this rule has no effect on that group.

## Verification after rollback

```powershell
Get-DlpComplianceRule -Identity "PII-Exchange-Audit-Encrypt-Exception"
```

Should return nothing. Confirm the parent policy's other three rules are still present and
unchanged (`Get-DlpComplianceRule -Policy "PII DLP - Exchange External Send Control"`), this
companion's removal should never affect them.
