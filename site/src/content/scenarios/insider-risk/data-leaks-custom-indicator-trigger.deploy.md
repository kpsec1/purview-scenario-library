#### `Send-InsiderRiskIndicatorRecord.ps1`

```powershell
#Requires -Version 7.0
<#
.SYNOPSIS
    Validates and uploads a pre-aggregated, third-party (non-Microsoft-workload) detection CSV to a
    Microsoft Purview Insider Risk Indicators (preview) connector, feeding a custom indicator used as
    a trigger and/or scoring indicator on the "Data leaks" Insider Risk Management policy template.

.DESCRIPTION
    Wraps Microsoft's own documented Insider Risk Indicators connector ingestion pattern (Microsoft
    Learn: import-insider-risk-indicators, "Step 4: Run the sample script to upload your data") as a
    parameterized, -WhatIf-capable PowerShell script, the same reasoning
    ../departing-employee-data-theft/deploy/Send-HrTerminationRecord.ps1 already applies to the sibling
    HR-connector surface. It does not call any Purview/Exchange/Graph PowerShell module cmdlet - this
    ingestion surface is a plain HTTPS webhook, not a PowerShell module.

    Unlike the HR-connector sibling script, this connector's CSV schema is NOT fixed by Microsoft - "The
    column names described in the following sections are examples, not required parameters. You can use
    any column names in your CSV files" (import-insider-risk-indicators). This script therefore takes
    the mandatory user-identifier and event-time column names as PARAMETERS instead of hard-coding them,
    and supports the two genuinely optional roles Microsoft documents: a Number-typed threshold column,
    and a Source column used to route one CSV's rows to multiple custom indicators (design.md §2 goal 2).

    Flow (matches the documented sample script family's behavior, confirmed via a direct fetch of
    https://github.com/microsoft/m365-compliance-connector-sample-scripts/blob/main/sample_script.ps1 -
    design.md §2 goal 5):
      1. VALIDATE the CSV client-side before any network call:
         a. -UserColumn and -EventTimeColumn are present in every row and non-empty.
         b. -EventTimeColumn values parse as ISO 8601 date-times.
         c. -ThresholdColumn values (if specified) parse as numbers for every row - the connector
            requires a Number data type for any field later used as a threshold.
         d. -SourceColumn values (if specified) are all present in -RelatedValues exactly - Microsoft
            documents a hard connector-side failure on a mismatch ("The connector fails if the column
            values don't match"); this check fails the same way client-side, before spending an upload
            attempt.
         e. No two rows share the same (-UserColumn, -EventTimeColumn) combination - Microsoft documents
            this as a SILENT drop with no error from the service ("the record is dropped"). This is the
            one failure mode in this pipeline the service itself will never surface, so this script
            fails closed on it by default (see -AllowDuplicateRecords).
      2. Acquire an OAuth 2.0 client-credentials access token from
         https://login.windows.net/<TenantId>/oauth2/token against the same fixed ingestion resource ID
         the HR-connector sibling script uses, independently confirmed identical for this connector by
         the direct GitHub fetch above (design.md §2 goal 5) - NOT re-derived from the HR-connector
         script by assumption.
      3. Split the validated CSV into chunks of at most -ChunkSize data rows (default 5,000, the
         generic sample script's own RecordsPerCall default - a different, more current figure than the
         HR-connector Learn page's own documented 500-row-per-file limit; see design.md §6) - a header
         row is added to every chunk.
      4. POST each chunk as multipart/form-data (field name "file") to
         https://webhook.ingestion.office.com/api/signals?jobid=<JobId>, bearer-authenticated with the
         token from step 2, over TLS 1.2.

    Idempotency note: as with the HR-connector sibling, re-ingestion/de-duplication behavior for an
    unchanged CSV re-uploaded on a subsequent scheduled run is NOT documented by Microsoft (VERIFY in a
    pilot tenant). Re-running this script is always SAFE in the sense that it never deletes or mutates
    existing tenant state - at worst it re-submits already-ingested rows. The ONE mutating side effect
    validated client-side (step 1e) protects against a documented DATA-LOSS mode, not an idempotency
    concern.

    Important: Microsoft's own guidance is to wait 24 hours after creating/updating the custom
    indicator(s) and associated policy before uploading data, to let all components sync -
    README.md §5 Step 6/§8; this script does not enforce that wait itself (it has no way to know when
    the portal-side configuration last changed) - the operator must observe it.

    This script never embeds a client secret. Pass it as a SecureString - never hard-code it or check
    it into source control.

    Author-only reference code. This script makes an outbound HTTPS call to
    webhook.ingestion.office.com whenever it runs WITHOUT -WhatIf. Always run with -WhatIf first.

.PARAMETER TenantId
    Microsoft Entra tenant ID (directory ID) - see docs/automation-surface.md for how to find it.

.PARAMETER AppId
    Application (client) ID of the Microsoft Entra app registered for this connector. This script does
    not create the app registration - reuse
    ../departing-employee-data-theft/deploy/Register-HrConnectorApp.ps1 (design.md §2 goal 6) - see
    README.md §5 Step 2.

.PARAMETER AppSecret
    Client secret for the app above, as a SecureString. Never pass in plaintext; never store in this
    repo or in an unencrypted file.

.PARAMETER JobId
    The Insider Risk Indicators connector's Job ID, generated when the connector is created in the
    Purview portal (README.md §5 Step 3).

.PARAMETER CsvPath
    Path to the pre-aggregated third-party detection CSV. Must contain at least -UserColumn and
    -EventTimeColumn; -ThresholdColumn and -SourceColumn are optional. This script does NOT perform the
    upstream aggregation - Microsoft only accepts preprocessed, already-aggregated data
    (design.md §7).

.PARAMETER UserColumn
    Name of the column containing the Microsoft 365 user's UPN/email address. Defaults to
    'UserPrincipalName'. Microsoft does not fix this column name for this connector - set it to match
    whatever your CSV actually uses.

.PARAMETER EventTimeColumn
    Name of the column containing the event/aggregation timestamp. Must be ISO 8601
    (yyyy-mm-ddThh:mm:ss.nnnnnn+|-hh:mm). Defaults to 'EventTime'.

.PARAMETER ThresholdColumn
    Optional. Name of the Number-typed column intended for use as a custom indicator's threshold value
    when you create the custom indicator in the portal (README.md §5 Step 5). If specified, every row's
    value in this column must parse as a number. Omit if this connector's data will only ever be used
    with the "Use only as a triggering event without any thresholds" option.

.PARAMETER SourceColumn
    Optional. Name of the column used to route different rows to different custom indicators from one
    CSV - Microsoft's own multi-indicator worked example (e.g. a column holding 'Salesforce' or
    'Dropbox'). Requires -RelatedValues.

.PARAMETER RelatedValues
    Required if -SourceColumn is specified. The exact, case-sensitive set of values -SourceColumn is
    allowed to contain - must match what you enter in the connector's own "Related values in source
    column" field in the portal exactly, per Microsoft's own documented failure mode (design.md §6).
    Case-sensitivity of the portal-side comparison itself is not documented by Microsoft - VERIFY
    (README.md §11); this script's own client-side check is intentionally case-sensitive (the stricter,
    fail-safer assumption).

.PARAMETER AllowDuplicateRecords
    Explicit opt-in to proceed with a real upload despite detected duplicate (-UserColumn,
    -EventTimeColumn) combinations. Without this switch, a real (non-WhatIf) run with duplicates present
    throws before acquiring a token or making any HTTP call. Duplicates are always reported under
    -WhatIf regardless of this switch, never silently ignored.

.PARAMETER ChunkSize
    Maximum data rows per uploaded chunk. Defaults to 5,000 - confirmed via a direct GitHub fetch of
    the generic sample_script.ps1's own RecordsPerCall default (design.md §2 goal 5), NOT the
    HR-connector Learn page's own different, page-documented 500-row figure.

.PARAMETER WhatIf
    Standard PowerShell ShouldProcess dry-run. Runs every validation in step 1 (schema, threshold
    numeric-parse, source-value match, duplicate-record detection) and reports the chunk plan - acquires
    no token and makes no HTTP call to the ingestion endpoint.

.EXAMPLE
    $secret = Read-Host -AsSecureString -Prompt 'Insider Risk Indicators connector app secret'
    ./Send-InsiderRiskIndicatorRecord.ps1 -TenantId $TenantId -AppId $AppId -AppSecret $secret `
        -JobId $JobId -CsvPath './third_party_alerts.csv' `
        -UserColumn 'User_Principal_Name' -EventTimeColumn 'Aggregation_Date' `
        -ThresholdColumn 'Alert_Count' -SourceColumn 'Source_Workload' `
        -RelatedValues 'Salesforce','Dropbox' -WhatIf

    Dry run reproducing Microsoft's own documented multi-indicator worked example (Salesforce +
    Dropbox from one CSV) - validates the CSV and reports the upload plan, sends nothing.

.EXAMPLE
    ./Send-InsiderRiskIndicatorRecord.ps1 -TenantId $TenantId -AppId $AppId -AppSecret $secret `
        -JobId $JobId -CsvPath './third_party_alerts.csv' `
        -UserColumn 'User_Principal_Name' -EventTimeColumn 'Aggregation_Date' `
        -ThresholdColumn 'Alert_Count' -SourceColumn 'Source_Workload' `
        -RelatedValues 'Salesforce','Dropbox'

    Uploads the CSV to the connector, chunked at 5,000 rows per call. Throws before any network call if
    duplicate (User_Principal_Name, Aggregation_Date) rows are found, unless -AllowDuplicateRecords is
    also passed.

.NOTES
    Grounded in Microsoft Learn and a direct GitHub source fetch (verify before production use -
    Microsoft describes the underlying sample script family as provided AS IS, unsupported under any
    standard support program):
    - Set up a connector to import third-party insider risk detections (preview) (three-step process,
      CSV column-name flexibility, mandatory UPN/event-time roles, Number-typed threshold column,
      Source-column multi-indicator pattern and its exact-match failure mode, UPN+timestamp uniqueness
      requirement, 24-hour post-update sync wait, webhook.ingestion.office.com firewall allowlist
      requirement):
      https://learn.microsoft.com/purview/import-insider-risk-indicators
    - Configure policy indicators in Insider Risk Management - "Custom indicators" section (custom
      threshold requirement, "Use only as a triggering event without any thresholds" option, no
      recommended/default thresholds for custom indicators):
      https://learn.microsoft.com/purview/insider-risk-management-settings-policy-indicators#custom-indicators
    - Sample script source (reference only - this script is an independent, parameterized
      reimplementation with connector-appropriate flexible schema handling, not a copy). Fetched
      directly during this build; confirmed IDENTICAL token endpoint template
      (https://login.windows.net/{tenantId}/oauth2/token), fixed resource ID
      (https://microsoft.onmicrosoft.com/86dfdabb-5089-4a0c-880a-cfa5a790c5b1), and webhook URL
      (https://webhook.ingestion.office.com/api/signals) to the already-grounded HR-connector sibling
      script; confirmed DIFFERENT default chunk size (5,000 via RecordsPerCall, vs. the HR-connector
      Learn page's own documented 500-row limit):
      https://github.com/microsoft/m365-compliance-connector-sample-scripts/blob/main/sample_script.ps1
    - ../departing-employee-data-theft/deploy/Send-HrTerminationRecord.ps1 - the sibling script this
      one's structure is deliberately parallel to, for a reviewer already familiar with that scenario.

    VERIFY before go-live: confirm re-ingestion/de-duplication behavior for an unchanged CSV
    re-uploaded on a subsequent scheduled run, in a pilot tenant; confirm whether the portal's own
    Source-column value comparison is case-sensitive (README.md §11, design.md §7).

    Requires PowerShell 7.0+, the same reason as the HR-connector sibling: Invoke-RestMethod's -Form
    parameter (multipart/form-data upload) is not available in Windows PowerShell 5.1.
#>
[CmdletBinding(SupportsShouldProcess, ConfirmImpact = 'High')]
param(
    [Parameter(Mandatory)]
    [ValidateNotNullOrEmpty()]
    [string]$TenantId,

    [Parameter(Mandatory)]
    [ValidateNotNullOrEmpty()]
    [string]$AppId,

    [Parameter(Mandatory)]
    [System.Security.SecureString]$AppSecret,

    [Parameter(Mandatory)]
    [ValidateNotNullOrEmpty()]
    [string]$JobId,

    [Parameter(Mandatory)]
    [ValidateScript({ Test-Path -LiteralPath $_ -PathType Leaf })]
    [string]$CsvPath,

    [Parameter()]
    [ValidateNotNullOrEmpty()]
    [string]$UserColumn = 'UserPrincipalName',

    [Parameter()]
    [ValidateNotNullOrEmpty()]
    [string]$EventTimeColumn = 'EventTime',

    [Parameter()]
    [string]$ThresholdColumn,

    [Parameter()]
    [string]$SourceColumn,

    [Parameter()]
    [string[]]$RelatedValues,

    [Parameter()]
    [switch]$AllowDuplicateRecords,

    [Parameter()]
    [ValidateRange(1, 5000)]
    [int]$ChunkSize = 5000
)

$ErrorActionPreference = 'Stop'

if ($SourceColumn -and -not $RelatedValues) {
    throw '-SourceColumn was specified without -RelatedValues - both are required together (design.md §6).'
}

# Fixed per Microsoft's documented ingestion flow, independently confirmed identical to the
# HR-connector sibling's own script via a direct GitHub fetch of sample_script.ps1 - design.md §2 goal 5.
$tokenEndpointTemplate = 'https://login.windows.net/{0}/oauth2/token?api-version=1.0'
$ingestionResource = 'https://microsoft.onmicrosoft.com/86dfdabb-5089-4a0c-880a-cfa5a790c5b1'
$webhookBaseUrl = 'https://webhook.ingestion.office.com/api/signals'

function ConvertFrom-SecureStringPlain {
    param([Parameter(Mandatory)][System.Security.SecureString]$Secure)
    $bstr = [System.Runtime.InteropServices.Marshal]::SecureStringToBSTR($Secure)
    try {
        return [System.Runtime.InteropServices.Marshal]::PtrToStringBSTR($bstr)
    }
    finally {
        [System.Runtime.InteropServices.Marshal]::ZeroFreeBSTR($bstr)
    }
}

# --- Step 1: Validate the CSV client-side before any network call ---
$rows = Import-Csv -LiteralPath $CsvPath
if ($rows.Count -eq 0) {
    throw "CsvPath '$CsvPath' contains no data rows."
}

$actualColumns = $rows[0].PSObject.Properties.Name
$requiredColumns = @($UserColumn, $EventTimeColumn)
if ($ThresholdColumn) { $requiredColumns += $ThresholdColumn }
if ($SourceColumn) { $requiredColumns += $SourceColumn }
$missingColumns = $requiredColumns | Where-Object { $_ -notin $actualColumns } | Select-Object -Unique
if ($missingColumns) {
    throw "CsvPath '$CsvPath' is missing required column(s): $($missingColumns -join ', ')."
}

$validationErrors = [System.Collections.Generic.List[string]]::new()

for ($i = 0; $i -lt $rows.Count; $i++) {
    $row = $rows[$i]
    $rowNum = $i + 2 # 1-based + header row

    if ([string]::IsNullOrWhiteSpace($row.$UserColumn)) {
        $validationErrors.Add("Row $rowNum`: '$UserColumn' is empty.")
    }

    $eventTimeRaw = $row.$EventTimeColumn
    $parsedTime = [datetimeoffset]::MinValue
    if ([string]::IsNullOrWhiteSpace($eventTimeRaw) -or
        -not [datetimeoffset]::TryParse($eventTimeRaw, [System.Globalization.CultureInfo]::InvariantCulture,
            [System.Globalization.DateTimeStyles]::RoundtripKind, [ref]$parsedTime)) {
        $validationErrors.Add("Row $rowNum`: '$EventTimeColumn' value '$eventTimeRaw' does not parse as ISO 8601.")
    }

    if ($ThresholdColumn) {
        $thresholdRaw = $row.$ThresholdColumn
        $parsedNumber = 0.0
        if (-not [double]::TryParse($thresholdRaw, [System.Globalization.NumberStyles]::Number,
                [System.Globalization.CultureInfo]::InvariantCulture, [ref]$parsedNumber)) {
            $validationErrors.Add("Row $rowNum`: '$ThresholdColumn' value '$thresholdRaw' is not numeric (required - the connector needs a Number data type for a threshold field).")
        }
    }

    if ($SourceColumn) {
        $sourceValue = $row.$SourceColumn
        if ($sourceValue -cnotin $RelatedValues) {
            $validationErrors.Add("Row $rowNum`: '$SourceColumn' value '$sourceValue' is not in -RelatedValues ($($RelatedValues -join ', ')) - Microsoft documents the connector failing outright on this mismatch.")
        }
    }
}

if ($validationErrors.Count -gt 0) {
    $validationErrors | ForEach-Object { Write-Host "  [FAIL] $_" -ForegroundColor Red }
    throw "$($validationErrors.Count) validation error(s) found in '$CsvPath' - fix before uploading. No network call made."
}

# --- Duplicate (UserColumn, EventTimeColumn) detection - a documented SILENT server-side drop ---
$duplicateGroups = $rows | Group-Object -Property { "$($_.$UserColumn)|$($_.$EventTimeColumn)" } |
    Where-Object { $_.Count -gt 1 }
if ($duplicateGroups) {
    $duplicateRowCount = ($duplicateGroups | ForEach-Object { $_.Count } | Measure-Object -Sum).Sum
    Write-Host "  [WARN] $($duplicateGroups.Count) duplicate ($UserColumn, $EventTimeColumn) combination(s) found, covering $duplicateRowCount row(s) total. Microsoft documents these as SILENTLY DROPPED on ingestion, not rejected with an error." -ForegroundColor Yellow
    $duplicateGroups | Select-Object -First 5 | ForEach-Object { Write-Host "         $($_.Name) ($($_.Count) occurrences)" -ForegroundColor Yellow }
    if (-not $WhatIfPreference -and -not $AllowDuplicateRecords) {
        throw "$($duplicateGroups.Count) duplicate record group(s) found - pass -AllowDuplicateRecords to upload anyway (the service will silently drop the extras), or de-duplicate the CSV first."
    }
}

# --- Compute the chunk plan ---
$chunks = @(for ($i = 0; $i -lt $rows.Count; $i += $ChunkSize) {
    , $rows[$i..([Math]::Min($i + $ChunkSize - 1, $rows.Count - 1))]
})
Write-Host "CSV '$CsvPath': $($rows.Count) record(s), $($chunks.Count) chunk(s) of up to $ChunkSize row(s), target JobId '$JobId'." -ForegroundColor Cyan

if ($WhatIfPreference) {
    for ($c = 0; $c -lt $chunks.Count; $c++) {
        Write-Host "  [WhatIf] Chunk $($c + 1)/$($chunks.Count): $($chunks[$c].Count) row(s) -> POST $webhookBaseUrl`?jobid=$JobId" -ForegroundColor Yellow
    }
    Write-Host 'WhatIf: no token acquired, no HTTP call made.' -ForegroundColor Yellow
    return
}

if (-not $PSCmdlet.ShouldProcess("Insider Risk Indicators connector JobId '$JobId'", "Upload $($rows.Count) record(s) in $($chunks.Count) chunk(s)")) {
    return
}

[System.Net.ServicePointManager]::SecurityProtocol = [System.Net.SecurityProtocolType]::Tls12

# --- Acquire an OAuth 2.0 client-credentials token ---
$plainSecret = ConvertFrom-SecureStringPlain -Secure $AppSecret
try {
    $tokenBody = @{
        client_id     = $AppId
        client_secret = $plainSecret
        grant_type    = 'client_credentials'
        resource      = $ingestionResource
    }
    $tokenResponse = Invoke-RestMethod -Method Post `
        -Uri ($tokenEndpointTemplate -f $TenantId) `
        -ContentType 'application/x-www-form-urlencoded' `
        -Body $tokenBody
}
finally {
    $plainSecret = $null
}
$accessToken = $tokenResponse.access_token
if (-not $accessToken) {
    throw 'Token acquisition succeeded but returned no access_token - check AppId/AppSecret/TenantId.'
}

# --- Upload each chunk as multipart/form-data ---
$uploadUri = "$webhookBaseUrl`?jobid=$JobId"
$tempDir = Join-Path ([System.IO.Path]::GetTempPath()) "irm-indicator-upload-$([guid]::NewGuid())"
New-Item -ItemType Directory -Path $tempDir | Out-Null
try {
    for ($c = 0; $c -lt $chunks.Count; $c++) {
        $chunkPath = Join-Path $tempDir "chunk-$($c + 1).csv"
        $chunks[$c] | Export-Csv -LiteralPath $chunkPath -NoTypeInformation

        $form = @{ file = Get-Item -LiteralPath $chunkPath }
        $headers = @{ Authorization = "Bearer $accessToken" }

        Write-Host "Uploading chunk $($c + 1)/$($chunks.Count) ($($chunks[$c].Count) row(s))..." -NoNewline
        $null = Invoke-RestMethod -Method Post -Uri $uploadUri -Headers $headers -Form $form -TimeoutSec 400
        Write-Host ' done.' -ForegroundColor Green
    }
}
finally {
    Remove-Item -LiteralPath $tempDir -Recurse -Force -ErrorAction SilentlyContinue
}

Write-Host "`nUpload complete: $($rows.Count) record(s) submitted to JobId '$JobId' in $($chunks.Count) chunk(s)." -ForegroundColor Cyan
Write-Host 'Verify ingestion in the Purview portal: Settings > Data connectors > (this connector) > Download log > check RecordsSaved.' -ForegroundColor Cyan
```
